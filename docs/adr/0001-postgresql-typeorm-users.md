# PostgreSQL как единственное хранилище; TypeORM для пользователей

Решение согласовано 2026-11-07 для первого блока задания по TypeORM.
MongoDB использовалась в первых версиях приложения и больше не нужна:
удаляем её реализации, зависимости, переключатели и тестовую инфраструктуру.

Чтение и запись пользователей переводим на TypeORM за существующими контрактами
репозиториев. Сессии устройств, блоги, посты, комментарии и реакции продолжают
работать через существующие raw SQL репозитории: это сохраняет работоспособность
приложения без заглушек и ограничивает объём миграции текущим заданием.

Сохраняем таблицу users, данные, идентификаторы, внешние ключи, мягкое удаление
и частичные уникальные индексы. Пересоздание таблиц ради структуры ORM нарушило
бы связи с остальными данными. Автоматическая синхронизация схемы отключена;
инициализация выполняется существующим db:init. Отдельный переход на систему
миграций TypeORM в этот этап не входит.

Access token по умолчанию живёт 5 минут. IP restriction отключён по умолчанию,
но может быть включён настройкой для следующих заданий.

Этот документ заменяет решение о сосуществовании MongoDB и PostgreSQL из
[описания предыдущего этапа](../superpowers/specs/2026-09-02-auth-sql-port-design.md).

## Следующий этап: auth и устройства

По последующему запросу пользователя сессии устройств также переведены на
TypeORM. IP-счётчики перенесены в PostgreSQL через TypeORM для общего лимита
между экземплярами приложения и полной очистки через testing/all-data.
Ограничения включены по умолчанию; первый блок доступен при явном отключении.
Блоги, посты, комментарии и реакции остаются на raw SQL.

## Уточнение требований второго блока (2026-11-08)

Пользователь предоставил точные требования: access token 10 секунд, refresh
20 секунд, IP restrictions включены. Они заменяют настройки первого блока.
Дефолты, пример окружения, локальные настройки и тесты обновлены.

## Третий этап: блоги и посты (2026-11-08)

По запросу пользователя блоги и посты (public GET и super admin CRUD) переведены
на TypeORM поверх существующих таблиц; отдельный SQL-сервис постов суперадмина
заменён CQRS use case'ами. Комментарии и лайки остаются на raw SQL, а в view
поста `extendedLikesInfo` заполняется заглушками (0 / None / []) — так требует
задание этапа. Дефолты возвращены к первому блоку: access TTL 5 минут,
IP restriction выключен (включается только явным `IP_RESTRICTION_ENABLED=true`).
Подробности — [typeorm-blogs-posts.md](../typeorm-blogs-posts.md).
