# Спек: завершение миграции DAL на TypeORM и «причёсывание» API (этап 6_4)

Дата: 2026-11-10. Ветка `6_4`. Термины — по `GLOSSARY.md`; продолжает
ADR `docs/adr/0001-postgresql-typeorm-users.md`.

## Problem Statement

После этапа 6_3 все репозитории работают через TypeORM, но в приложении
остались следы прежних хранилищ: прямой `pg`-пул для `testing/all-data` и
`db:init`, абстрактные контракты репозиториев и интерфейсы сущностей,
нужные когда-то для переключения Mongo/SQL, хелпер сортировки в каталоге
`sql/`, мёртвые Mongo-спеки и неработающий lint. Публичный API содержит
эндпоинты, которых нет в контракте инкубатора (`/users`, запись в `/blogs`,
`/app`). Задание этапа: завершить миграцию DAL, привести API в соответствие
документации (public api + super admin api) и пройти автопроверку. Access
token ≥ 5 минут, IP-restriction выключен.

Документации в репозитории нет; набор эндпоинтов ветки `5_4` совпадает с
текущим, поэтому чек-лист соответствия строится по стандартному контракту
инкубатора «Blogger platform with admin», а финальная проверка — прогон
автотестов пользователем.

## Solution

Приложение обращается к PostgreSQL только через TypeORM. Публичный API
только читает (кроме реакций, комментариев и auth), все операции
суперадминистратора живут под `/sa`. Слои контрактов Mongo-эпохи убраны,
модули `user-accounts` и `bloggers-platform` устроены одинаково. Мёртвые
тесты удалены, lint работает. Новая e2e-спека проходит каждый эндпоинт
контракта и фиксирует коды, формы ответов, пагинацию и валидацию.
Поведение API для автотестов не меняется.

## User Stories

1. Как суперадминистратор, я хочу управлять пользователями только через `/sa/users`, чтобы API совпадал с документацией.
2. Как суперадминистратор, я хочу управлять блогами и постами только через `/sa/blogs`, чтобы публичный `/blogs` был только для чтения.
3. Как читатель, я хочу, чтобы публичные `/blogs`, `/posts`, `/comments` не принимали записи от суперадминистратора, чтобы контракт был однозначным.
4. Как клиент автотестов, я хочу, чтобы `/testing/all-data` очищал все таблицы и отвечал 204.
5. Как клиент автотестов, я хочу получать `Paginator` с полями pagesCount, page, pageSize, totalCount, items на всех списковых эндпоинтах.
6. Как клиент автотестов, я хочу, чтобы дефолты query-параметров (pageNumber 1, pageSize 10, sortBy createdAt, sortDirection desc) и фильтры поиска работали на всех списках.
7. Как клиент автотестов, я хочу получать 400 в формате `errorsMessages` на каждом эндпоинте с телом, с указанием поля.
8. Как клиент автотестов, я хочу получать 401 на basic-эндпоинтах без/с неверными учётными данными и на bearer-эндпоинтах без/с неверным токеном.
9. Как клиент автотестов, я хочу получать 404 на несуществующие и некорректные id на всех эндпоинтах с id.
10. Как пользователь, я хочу получать на логине accessToken в теле и refreshToken в httpOnly secure cookie.
11. Как пользователь, я хочу видеть в `/auth/me` поля email, login, userId.
12. Как пользователь, я хочу видеть в `/security/devices` поля ip, title, lastActiveDate, deviceId.
13. Как пользователь, я хочу, чтобы access-токен жил не меньше 5 минут.
14. Как клиент автотестов, я хочу, чтобы частые запросы к auth не отбивались 429.
15. Как разработчик, я хочу, чтобы приложение обращалось к базе только через TypeORM.
16. Как разработчик, я хочу, чтобы `user-accounts` и `bloggers-platform` зависели от репозиториев одинаково, без абстрактных контрактов.
17. Как разработчик, я хочу, чтобы `yarn lint`, `yarn build` и полный e2e проходили.
18. Как разработчик, я хочу, чтобы в репозитории не было исключённых мёртвых спек и закомментированных роутов.

## Implementation Decisions

- `testing/all-data` выполняет TRUNCATE через TypeORM `DataSource`; `db:init`
  применяет `init.sql` через `DataSource`. `DatabaseModule` и `PG_POOL`
  удаляются; `pg` остаётся только драйвером TypeORM. Тестовые хелперы, которые
  инжектили пул, используют `DataSource`.
- Удаляются контроллер `/users` (и неиспользуемые после этого use case'ы и
  запросы), write-методы публичного `/blogs`, `/app` с `AppService`,
  закомментированные роуты в `posts.controller`, `global-prefix.setup`.
- В `user-accounts` абстрактные классы-контракты репозиториев и интерфейсы
  `UserEntity`/`DeviceSessionEntity` удаляются; use case'ы, запросы, guards и
  сервисы зависят от TypeORM-репозиториев и сущностей напрямую. Хелпер
  сортировки пользователей переезжает в `typeorm/query`, пустые каталоги
  удаляются.
- Мёртвые спеки (`blogs`, `posts`, `comments`, `app` e2e и
  `app.controller.spec`) удаляются, `testPathIgnorePatterns` сводится к
  `node_modules`. `UsersTestManager` и спеки переводятся на `/sa/users`.
- eslint: конфиг приводится к установленным пакетам (или доустанавливается
  `typescript-eslint`), найденные замечания исправляются.
- Новая e2e-спека `api-conformance` на стандартном шве проходит контракт по
  эндпоинтам; найденные расхождения исправляются в коде.
- Схема БД, семантика реакций и писем, дефолты TTL/IP не меняются.

## Testing Decisions

- Шов прежний: e2e через `initSettings` + supertest поверх временного
  PostgreSQL (`yarn test:e2e:local`).
- `api-conformance.e2e-spec.ts`: для каждого эндпоинта public и sa API —
  успешный код и форма ответа, дефолты и валидация query, 400/401/403/404,
  cookie refresh-токена, `/auth/me`, `/security/devices`, `testing/all-data`.
- Существующие спеки остаются и переводятся на `/sa/*` там, где нужно.
- Перед завершением: `yarn lint`, `yarn build`, полный `yarn test:e2e:local`.

## Out of Scope

- Новая функциональность; изменение схемы БД; система миграций TypeORM.
- Изменение TTL/IP (только фиксация в документах); деплой и настройка URL
  в инкубаторе.
- SMTP и письма.
