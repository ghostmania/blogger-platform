# TypeORM: auth, IP restrictions, devices и testing

Продолжение миграции пользователей. URL и HTTP-контракты auth и
`/security/devices` сохранены.

## Изменения

- Сессия устройства — `DeviceSession` Entity существующей таблицы `device_sessions`.
  Чтение и запись переведены с raw SQL на два TypeORM-репозитория.
- `GET /security/devices` возвращает активные сессии текущего пользователя.
  Удаление чужого устройства возвращает 403, отсутствующего — 404.
- Login создаёт отдельную сессию; refresh сохраняет deviceId и название устройства,
  обновляет IP и даты. Logout и удаление устройства отзывают refresh-токен.
- Refresh проверяет принадлежность и срок жизни сессии, версию токена и наличие
  неудалённого пользователя. Обновление выполняется условным UPDATE по предыдущей
  версии: из двух одновременных refresh только один успешен. Удалённая между
  проверкой и UPDATE сессия не создаётся заново.
- IP restrictions включены по умолчанию: не больше 5 запросов за скользящие
  10 секунд на сочетание IP и auth endpoint. Шестой запрос получает 429.
  Неуспешная авторизация также расходует лимит. Повторные отклонённые запросы
  не продлевают окно ограничения.
- `TypeOrmThrottlerStorage` сохраняет счётчики в `ip_restrictions`. Транзакция
  с блокировкой строки защищает лимит от одновременных запросов; счётчики общие
  для экземпляров приложения, использующих одну БД. Ключ формирует Nest Throttler
  из IP, контроллера, обработчика и имени ограничения.
- `DELETE /testing/all-data` возвращает 204 и очищает пользователей, сессии,
  блоги и зависимые посты/комментарии/реакции, а также IP-счётчики. Повторный
  вызов допустим, старые refresh-токены больше не действуют.

## Перед запуском

Выполнить `yarn db:init`: в существующую схему добавляется таблица
`ip_restrictions`, данные не удаляются. `synchronize` остаётся выключенным.

```dotenv
ACCESS_TOKEN_TTL=5m
REFRESH_TOKEN_TTL=20s
IP_RESTRICTION_ENABLED=true
```

TTL оставлен по ранее согласованным значениям. Если следующая автопроверка
требует access 10 секунд, задать `ACCESS_TOKEN_TTL=10s` и перезапустить приложение.
Для первого блока можно явно отключить ограничения: `IP_RESTRICTION_ENABLED=false`.
Настройки окружения сервера имеют приоритет над дефолтами.

## Проверки

```bash
yarn build
yarn test:e2e:local
```

Тесты запускаются во временном локальном PostgreSQL. Новая suite
`test/auth-stage-two.e2e-spec.ts` покрывает очистку ограничений, разные IP,
конкурентные запросы, общие счётчики, отзыв токенов после очистки/удаления
пользователя, истёкшие сессии и гонку refresh с удалением сессии.

Записи IP-ключей остаются в таблице после истечения окна; старые timestamps
отфильтровываются при следующем запросе к ключу. Плановая очистка неактивных
ключей в этот этап не входит. `testing/all-data` удаляет их полностью.
