# TypeORM: комментарии и реакции

Четвёртый этап миграции. URL и HTTP-контракты не менялись; предыдущие этапы —
[пользователи](typeorm-users.md), [auth, устройства, IP restrictions](typeorm-auth-devices.md),
[блоги и посты](typeorm-blogs-posts.md). Термины — в [GLOSSARY.md](../GLOSSARY.md).

## Что изменено

- `Comment` — TypeORM Entity поверх таблицы `comments` (bigint id строкой,
  `ManyToOne` на пост и на автора с `onDelete: CASCADE`, денормализованный
  логин автора). Создание, правка и удаление — через `CommentsTypeOrmRepository`
  и методы сущности; чужой комментарий даёт 403, нечисловой или несуществующий
  id — 404 до обращения к БД.
- `PostLike` и `CommentLike` — Entity поверх `post_likes` и `comment_likes`
  с общим абстрактным базовым классом `Like` (пользователь, статус, время).
  Один `LikesTypeOrmRepository` обслуживает обе таблицы: ищет реакцию пары
  «цель – пользователь», при том же статусе ничего не пишет, при другом меняет
  статус и время, при отсутствии вставляет; конфликт первичного ключа от
  одновременных одинаковых запросов обрабатывается одним повтором. Строки со
  статусом None остаются.
- Чтение реакций: счётчики и «моя реакция» — коррелированные подзапросы в
  QueryBuilder (`getRawAndEntities`) для постов и комментариев; «последние
  лайки» — один дополнительный запрос по id постов страницы (`ROW_NUMBER()`
  внутри поста, не более трёх, join на `users` с `withDeleted`). «Моя реакция»
  запрашивается только для авторизованного читателя.
- View поста больше не заглушка: `GetPosts`, `GetBlogPosts`, `GetPostById`
  передают id текущего пользователя в репозиторий.
- Удалены raw SQL репозитории комментариев и реакций, утилита дельты
  счётчиков, самодельные спеки `comments-likes-sql` и `create-comment`, скрипт
  `run-comments-sql-tests.sh` и команда `test:comments:sql`.

## Настройки

Схема БД не менялась, `synchronize: false`, `yarn db:init` повторять не нужно.
Дефолты прежние и проверены в коде, `.env.example` и production Vercel:

```dotenv
ACCESS_TOKEN_TTL=5m
REFRESH_TOKEN_TTL=20s
IP_RESTRICTION_ENABLED=false
```

## Проверки

```bash
yarn build
yarn test:e2e:local
```

Новая suite `test/typeorm-comments-likes.e2e-spec.ts` (стандартный шов
`initSettings` + временный PostgreSQL): маппинг сущностей на существующие
таблицы, создание комментария с отбрасыванием подделанных полей автора, CRUD
автором, 403 для чужого, пагинация и сортировка списка комментариев поста,
конкурентные и меняющиеся реакции для постов и комментариев, последние лайки
(порядок, стабильность при повторном лайке, совпадение со списками), 404 для
невалидных id, 401 для записей без токена, 400 в формате `errorsMessages`,
очистка через `testing/all-data`, чтение legacy-строк с большими id,
лайки мягко удалённого пользователя остаются видимыми, каскад при удалении
поста.
Отчёт о прогоне — [verification/typeorm-comments-likes.md](verification/typeorm-comments-likes.md).
