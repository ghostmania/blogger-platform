## Ревью (две оси: стандарты и спек)

Подтверждённые и исправленные замечания:

- `withDeleted()` стоял после `innerJoin(User)`: TypeORM добавляет условие
  `deleted_at IS NULL` в момент вызова `join()`, поэтому лайки мягко удалённых
  пользователей выпадали из «последних лайков», но считались в `likesCount`.
  Порядок вызовов исправлен, добавлен e2e-сценарий с удалением пользователя.
- В карточке поста ключ «последних лайков» брался из URL (`/posts/007` терял
  лайки) — теперь из id сущности.
- Use case реакции на пост проверял существование поста тяжёлым запросом
  с подзапросами реакций — заменён на `findOrNotFoundFail` пишущего репозитория.
- FK-ошибка при удалении цели между проверкой и вставкой реакции давала 500 —
  теперь 404. Фабрика сущности вызывалась ради чтения статуса — статус
  передаётся явно, метод переименован в `upsert`.
- Сорт-хелпер комментариев приведён к имени `resolveSortExpression` как у
  блогов/постов; в документе 6_2 «лайки» в значении «любые реакции» заменены
  на «реакции» по глоссарию. Добавлен сценарий каскада при удалении поста.

Отклонено (осознанно): дублирование `withLikes`/`toView` между постами и
комментариями и четвёртая копия `resolveSortDirection` — общий helper
потребовал бы править блоги/посты вне этапа; время реакции ставится часами
приложения (`new Date()`), а не `clock_timestamp()` — инстансы в одном регионе,
расхождение часов для порядка лайков несущественно; проверки метаданных
DataSource и числа строк реакций в e2e повторяют стиль `typeorm-blogs-posts`.

После правок: `tsc` и `yarn build` без ошибок; suite `typeorm-comments-likes`
— 20 тестов; полный e2e — **10 suites, 114 passed — PASS** (74.5 s).
